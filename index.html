How I think about product

The most useful thing I've learned so far isn't a framework — it's noticing when I've fallen in love with my own idea instead of the user's problem.

I started as a marketing intern who got promoted for turning user feedback into product decisions, not just campaign results. Since then I've solo-founded an app, watched it get real usage numbers that turned out to be hollow, re-read my own research with fresh eyes, and found the actual signal I'd missed the first time.

I'd rather run a scrappy, half-fake test with 15 real users than build the full version of something nobody asked for. That's the thread running through everything below — the failures included.

Customer Obsession
21 user interviews at Eva Bharat, 30+ in-person interviews for Fitstreak, a WhatsApp tool designed around how shopkeepers already work — not how I wanted them to work.
Are Right, A Lot — and Say So When You're Not
Fitstreak looked like a success at 300 users. Admitting only 12 were real, and that I'd been chasing my own idea, is the decision I'm most proud of.
Bias for Action
Validated the diet-app pivot with a manually-run Wizard of Oz test on 15 users before writing a line of new product code.
Featured Case Study

Fitstreak: building the wrong thing well, then finding the right thing

Solo Founder · Aug 2025 – Oct 2026 · Market research, product design, engineering, research re-analysis
What the numbers said
300 users
Gym-to-gym growth from 21 surveys and ~30 in-person interviews. Looked like traction.
→
What was actually true
12 users
Showed genuine daily engagement. No PMF, no monetization, high churn — I'd built for my idea of fitness, not theirs.
The build
Researched and built a workout-tracking fitness app, driving growth to 300 users gym by gym. Pitched it at the EO GSEA Summit and reached the finals.
The signal I ignored
Only 12 users were genuinely engaging daily. I'd fallen in love with the workout idea instead of listening to what users actually needed — no product-market fit, no monetization path, high churn.
The re-analysis
Instead of collecting new data to chase a new idea, I went back and re-read my own Fitstreak research. Users had been asking about diet, not workouts — a signal I'd missed the first time because I was attached to the original idea.
De-risking the pivot
Before writing new product code, I ran a Wizard of Oz MVP with 15 users — manually creating AI-assisted diet plans by hand to simulate the product. It validated real demand and confirmed the pivot direction.

Things I've built that people actually use

Side projects where the test wasn't "does it work," it was "does anyone open it twice."

AI Video-to-Storyboard Connector
Built for Eva Bharat · Daily use by 5 designers
AI models like Claude can't natively watch video. I built a tool that converts short clips (≤30s) into a single 9-frame storyboard image so an AI model can interpret the video content. Deployed internally, where 5 designers now use it daily to speed up creative feedback loops.
WhatsApp Khata-to-Ledger Automation
Personal project
Small shop owners already keep accounts by hand in a khata notebook — asking them to adopt a new app is a real barrier. This tool lets them send a photo of the handwritten khata over WhatsApp; the system auto-generates structured digital accounts, with voice-note corrections for any ambiguous entries. Meets users in their existing workflow instead of forcing migration.
Codebase Visualizer for AI-Generated Code
Personal tool · Daily use
Understanding a codebase by repeatedly querying an LLM is slow and expensive. Converts AI-generated code into a compact JSON representation plus an interactive chart / code-tree, so I can understand a codebase's structure without re-querying a model every time.
Guru — Interactive Tool-Learning System
Personal project · Prototype, PS1/JavaScript
Passive video tutorials don't teach muscle memory. Built a prototype that guides a user's cursor step-by-step through real software, teaching tool usage interactively instead of having them watch and forget.
